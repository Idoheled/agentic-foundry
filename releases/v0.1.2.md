# Agentic Foundry v0.1.2

Local release-workflow materialization correction. The pinned `2026-11-20-r5` runtime payload, native deployment behavior, and existing-machine Claude → OMP workflow are unchanged. The source-archive fix introduced in `v0.1.1` is retained.

## What changed

- Local-mode release preparation explicitly runs `git lfs checkout` after fetching the required objects and selecting the verified commit.
- The local cache is materialized into the working tree before the existing object and reconstructed-file hash checks run.
- A regression covers real cached LFS objects and a repeated checkout that leaves pointer files in the working tree.
- Recommended versioned checkout, deployment-state, tag, and standalone-export examples now use `v0.1.2`.

This distinguishes successful object acquisition from usable working-tree content. Materialization does not waive payload verification or replace missing bytes with an assumed success.

## Why this is a new patch version

The `v0.1.1` local-mode publication attempt fetched all Git LFS data into the cache. A second checkout of the same commit left small LFS pointer files in the working tree, so payload verification blocked before release creation. The explicit materialization step addresses that workflow failure.

The protected `v0.1.0` and `v0.1.1` tags, their committed release notes, and historical provenance remain unchanged. The correction is recorded under a new version instead of moving an earlier tag.

Source archive creation continues to read the selected commit's raw Git blobs and preserve canonical LFS pointers bound to its offline manifest. The `v0.1.1` correction preventing source archives from expanding into multi-gigabyte runtime data is retained.

## Payload and acceptance scope

The selected tools, images, native packages, source snapshots, dependencies, licenses, and artifact identities are unchanged. Private repositories remain preferred; native package ownership, existing brain/hooks/skills/model-route preservation, and the manual Claude-to-OMP handoff remain in force. No new monitoring, telemetry, backup, or replacement memory platform is introduced.

The complete fallback and evaluation/browser profile target Debian 13 on x86-64/glibc. Other distributions, ARM64 and musl require matching qualified private profiles or payload builds.

This workflow correction adds no claim of new target qualification. Actual native upgrades, internal-model protocol/tool behavior, Docker worker execution, real project delivery, and configuration preservation remain receiving-host acceptance checks. Real browser interaction was blocked in the builder environment; the supplied sandbox-enabled target UI test remains required.

## Get started

Select the `v0.1.2` tag and follow the repository README, `docs/QUICKSTART.md`, and `docs/PAYLOADS.md`. Retrieve, materialize, and verify the real LFS objects before moving the checkout into a disconnected environment. Keep private site configuration and credentials outside Git.

To create one transferable offline kit, hydrate a clean checkout at `v0.1.2` and run `build-tools/export-release.py --ref v0.1.2` with an absolute output path outside the tracked source tree. The exporter checks source and payload identities, includes one copy of the complete payload, rereads the tar members, and emits the checksum and validation report.
