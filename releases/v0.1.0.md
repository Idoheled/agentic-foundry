# Agentic Foundry v0.1.0

First repository release of the disconnected workspace installer and its pinned r5 payload.

## Included

- One deployment entry point for a fresh machine and an existing workspace, with factual discovery, private supply preference and repeatable staged installation.
- The preserved Claude → OMP upgrade: Claude upgrades and qualifies OMP, writes the handoff and stops; the operator switches to OMP to complete the remaining stack.
- Paperclip coordination, OMP, Claude Code, Codex, OpenCode, PostgreSQL and optional Herdr, with native tooling and reviewed skills/hooks.
- Worktrunk, RTK OSS, Zoekt and Universal Ctags; seven language services; Inspect AI and a native-agent benchmark; Playwright and Chromium; Trivy's offline database/checks; and the Go SDK.
- Complete declared runtime dependency payloads, selected upstream source snapshots, licenses, provenance and offline documentation.
- Content-addressed Git LFS objects, a manifest bound to the payload lock, integrity verification and offline hydration.
- Source-only CI, annotated release tags, maintainer ownership, issue/PR templates and guarded release publication.

No new telemetry, monitoring or backup platform is introduced. Existing transaction recovery and configuration originals remain part of a correct upgrade.

## Qualification

The r5 baseline passed 197 controller tests and a separate 197-test source-only run. Eight real productivity tool groups installed into an isolated prefix, exposing 27 commands and passing 89 checks. All eight installed runtime identities were verified. The offline native fallback contains 426 package files; an empty-status native package resolution acquired 353 packages from the local repository without installing them on the builder.

Real functional checks covered worktrees, repository/symbol search, seven language-service protocol flows, compact-output failure propagation, offline dependency scanning, Inspect scoring and native benchmark subprocesses. Repository-specific payload and release-tool checks are additional evidence recorded by their CI runs.

## Supported profile

The supplied compiled fallback targets Linux x86-64 with glibc, with Debian 13 native packages and the qualified evaluation/browser profile. Other distributions, ARM64 and musl need matching qualified private payload profiles. Detection is dynamic; binary compatibility is never assumed.

## Target acceptance remains explicit

Private model routes, native-client protocol compatibility, actual Docker worker execution, real project tasks and the preservation of the target machine's configuration must be checked onsite. The builder checked Chromium bytes, dependencies, version and relocation, but its environment blocked the required Unix socket operation for real UI interaction. The included target browser gate keeps sandboxing enabled and must pass before browser capability is accepted.

The payload contains declared runtime/source closures, not every optional upstream build graph, all Git history, arbitrary future project dependencies, model weights, the proprietary Claude Code implementation source or the optional Trivy Java class index.

## Getting started

Read the repository README and `docs/QUICKSTART.md`, then select the fresh-machine or existing-workspace path. Supply actual private repository findings and internal model configuration; keep credential values outside Git. Read `docs/PAYLOADS.md` before transferring a source checkout into a disconnected environment.
